The public Render pair was switched from the ephemeral SQLite files to one managed
Postgres instance. This is the record of that deployment and its evaluation.

overlap. The three gate guarantees are PL/pgSQL triggers, not application checks.

## Verification

- `GET /api/health` returns `{"database": "postgres", ...}`.
- `GET /healthz` returns `{"database": "postgres", ...}`.
- The full harness ran against the public URLs:

  ```bash
  set -a; . deploy/.secrets.env; set +a
  RTI_AGENT_URL=https://rti-pilot-agent.onrender.com \
  RTI_PORTAL_URL=https://rti-pilot-portal.onrender.com \
    python -m scripts.run_eval --json-out artifacts/eval_remote_postgres.json
  ```

  Result: **16/16 passed** — filing, payment, the token-less payment rejection, the
  Section 6(3) transfer, the Section 19 appeal and both review decisions.

- The 16 stored results were still present after restarting the agent, which is the
  point of the switch: a restart no longer resets the run data.
- The earlier SQLite-hosted result remains in `artifacts/eval_remote.json`; this run is
  in `artifacts/eval_remote_postgres.json`, with environment metadata in
  `artifacts/eval_remote_postgres.meta.json`.

## Limits and next step

- The database is free and expires on **2026-11-21**. Before then, upgrade it or point
  both services at another managed Postgres; the same `RTI_DATABASE_URL` switch applies.
- This switch started with empty tables. Existing SQLite rows are not copied on boot;
  `python -m scripts.migrate_to_postgres` performs the one-time copy while the services
  are stopped.
- Provider snapshots/PITR are the backup path on Postgres. `scripts/backup_db.py` is
  SQLite-only.
